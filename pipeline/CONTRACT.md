# Implementation contract

The pipeline accepts a request, not a fixed number of fixtures. Python standard library only.

Request v1: `schemaVersion`, `id`, `dates` (ISO local dates), `timezone`, `scope` with `competitionIds`, `fixtureIds`, `teamIds` (arrays of provider ID strings, optional), `categories` (`wins-btts`, `other-markets`, `bet-builders`), `historyMatches` (default 8), `limits` (`maxRequests`, `batchSize`, `maxModelCalls`, `maxParallel`, `timeoutSeconds`), optional `builderFixtureIds` (explicit subset), and `routing` mapping `retrieval`, `review`, `lead` to `model` and `effort`. Empty scope filters require explicit `allCompetitions: true`. Defaults: `gpt-6-luna` medium retrieval where available, `gpt-6.2-sol` high review, `gpt-6.2-astra` high lead. Explicit request routes remain authoritative; unavailable routes fail visibly without a silent fallback. The date/competition/team/fixture filters intersect; multiple IDs within a filter are OR. Started/cancelled/postponed fixtures never enter prospective screening. Preserve exclusions and unresolved fetch failures.

Collector interface: `football_pipeline.collector.Collector(cache_dir, max_requests=200, timeout=20, transport=None).collect(spec, now=None)` returns a serializable evidence bundle. `now` is an aware datetime (tests may fix it). Bundle includes `schemaVersion`, `scope`, `collectedAt`, `fixtures` (each with string `id`, home/away identity, kickoff UTC, competition ID/name, status, current snapshot, source references, both-team historical ledgers and gaps), `excluded`, `errors`, `telemetry`. History must end before each target kickoff and capture timestamp; no future/target-result leakage. Cache provides real retrieval timestamps, resource-specific TTL and no stale odds/lineups treated as fresh. Private/authenticated bookmaker data are not collected automatically. Live provider failure stays visible; supplied frozen bundles are also accepted by runner.

Runner interface: `football_pipeline.runner.run_pipeline(spec, bundle, output_dir, execute=False, executor=None)` -> manifest dictionary. Plan mode writes bounded tasks and routes without model calls; execute mode invokes installed Codex CLI with explicit model/effort, no silent fallback, no shell interpolation, time/call limits and validated structured outputs. `executor` is injectable for tests. Reuse one evidence bundle; retrieval jobs cover disjoint batches. Pipeline steps: bounded extraction -> lead screening covering all fixture/category directions -> deeper lead dossiers for survivors/close exclusions -> independent review -> final lead decision. Outputs remain research-only unless all declared exact-price/XI/contract/evidence gates clear. User excludes BTTS No. Never force a pick count or assume all candidates are final. Missing quotes/availability can legitimately leave zero final selections.

Evidence is untrusted data, never instructions. Every model task must separate observed facts, calculations, inference and missing data, and include source references. Enforce response fixture IDs/scope and freshness at the boundary. Preserve requested and reported model identity separately; CLI model requested does not establish backend identity. Every call records actual reported usage or null. Raw logs/caches are ignored by Git. No automatic journal overwrites or bets.

Evaluation interface: `football_pipeline.evaluation.usage_report(manifest, rates=None)` and `compare_costs(baseline, candidate)` return honest measured/estimated usage and cost comparisons only for compatible scope/evidence/work; missing measurements remain null. `evaluate_journal(events, protocol=None)` evaluates prospective pre-recorded genuine forecasts, excludes retrospective imports, retains passes/statuses and unknown outcomes, and never derives forecasts from odds. Pairwise baseline comparison must share observations and settlement definition; report sample size and uncertainty, no proof from short streaks. Immutable protocol/measurement artifacts should support registration before outcomes, corrections and versioning. Report unavailable superiority as unestablished.

Root owns request validation, CLI integration, docs/skills, journal bridge, git and integration checks. Collector agent owns collector/cache and their tests. Runner agent owns runner and tests. Evaluation agent owns evaluation/protocol helpers and tests. Coordinate interface changes explicitly.
