# Journal — read first

**Purpose:** preserve research decisions, verify outcomes and learn from specific process failures.

**Process:** read project preferences and active lessons → archive original evidence/status → append sourced results → review wins and losses → record testable improvements → validate.

- Preserve candidates, reserves, passes and final selections, including zero-final slates. Changes are appended; historical decisions are not rewritten.
- Separate retrospective imports from records actually captured before kickoff.
- Distinguish the ordinary event outcome, eligible promotional result and actual bookmaker settlement. A two-goal lead applies only to an eligible result leg.
- Keep winning passes and losing watches visible. New historical data retrieved after a match belongs in the review, not the original forecast.
- Review process separately from outcome; a short winning streak does not establish an edge.

**Output:** validated JSON events, source-linked outcome reviews, unresolved facts and specific lessons for future evaluation. The active project supplies `journal/README.md`, `journal/active-lessons.md` and `scripts/journal.py`.

**Roles:** bounded workers retrieve results; code validates records; the reasoning lead judges methodological changes. No UI or recurring job runs automatically.
